# v0.1.2 hardening qualification

The initial confirmed fixes were committed separately as `3d5f020`, after four
new regressions failed against v0.1.1 and then passed. Local verify passed at
`.local-ci/20261117T055605.522437Z-verify/report.json`.

## Findings fixed

| Finding | Resolution / regression |
| --- | --- |
| A single NaN policy sample creates an invalid transition but poisons PPO parameters despite masking | Reject any invalid rollout and nonfinite learning inputs before optimizer mutation. Check loss and gradient finiteness before each optimizer step. Tests preserve parameters and empty optimizer state on rejection. |
| Config assignment reports a different dt from native execution | Public config is a read-only copied snapshot; updates use validated configure. |
| configure(seed=...) changes metadata without reseeding | Reject seed changes during configure; explicit seed() is tested against a fresh seeded environment. Rejected setup preserves state and captured execution. |
| Same-shape transpose bypasses pointer/shape guard | Kernel binding checks strides, dtype, device and autograd metadata as well. |
| Replaced policy parameters, rollout history or workspace silently leave graphs/kernels using old storage | Retain original storage and check signatures before collection, direct inference and GAE. Reconstruct Rollout when changing storage/architecture; in-place learning still works. |
| Direct auto_reset assignment changes wrapper accounting without native behavior | Read-only mode property; set_auto_reset updates native execution and invalidates graph use. |
| Replaced environment actions/outputs silently disagree with bound native buffers | Check bindings before submission and pending-step collection, while retaining original allocations. |
| Negative gradient norm can reverse gradients | Validate finite coefficient domains and positive gradient norm before updating. |

The follow-up replacement/autoreset/environment regressions also failed before
the corresponding guards were implemented. The resulting suite contains 28 RL
acceptance cases, including 12 hardening cases. No simulation equations, frozen
tensor shapes, original oracle or numerical tolerances changed.

PPO uses strict batch rejection, not partial learning from corrupt samples. GAE
continues to support invalid masks for diagnostics. Finite loss/gradient checks
apply to each epoch; there is no rollback of earlier successful epochs if a
later epoch fails, nor a guarantee against an arbitrary custom optimizer writing
bad values. This bounded example is not a general transactional RL framework.

## Follow-up scan and evidence

Reviewed the surrounding configuration ownership, reset/step sequencing, graph
invalidation, pending-step outputs, storage lifetime, policy parameter updates,
GAE inputs, optimizer rejection and installed training paths. After the fixes,
the scoped regression scan has no remaining reproducible findings. This is not
an exhaustive proof that the simulator is bug-free.

Sustained training: 1,024 environments, 128 steps, 30 updates (3,932,160 collected
transitions) completed with finite losses and valid samples. Log/checkpoint:
`.local-ci/hardening-training.log`, `.local-ci/hardening-policy.pt`. This tests
repeated graph replay across optimizer updates, not convergence or sim-to-real.

Final grouped benchmark: `.local-ci/rl-20261117T060051.545036Z/report.json`,
32 steps, two PPO epochs, five samples/two warmups, A=1,024, N=1,024/16,384,
CPU eight threads with the same GPU learner. Both downstream differential and
1.15x timing-bracket gates passed. GPU collection medians were 5.417/7.674 ms;
whole iterations 10.116/37.049 ms. Relative to this particular CPU configuration,
speedups were 3.26x/4.71x. This is not a repeated exhaustive best-CPU sweep.
New learner checks add deliberate update-boundary work; do not silently reuse
older whole-iteration timings as v0.1.2 results.

Independent Nsight traces at both sizes passed allocation/copy/launch gates:
resident collection still has no host/device copies or CUDA allocations/frees.
Tensor metadata guards do no device reads or per-step host synchronization.
The earlier intermediate check `rl-20261117T055904.626114Z` also passed; the final
report includes pending-step guards and coefficient validation.

The final verify/release reports are saved under `.local-ci/` and identified by
the implementation commit and release-check output. Verify includes the frozen
CPU/native/core suites, 28 RL tests and fresh installed train/save/load/evaluate.
README/package versions are 0.1.2. No remote push, publication or tag is implied.

## Remaining qualification limits

A subsequent [repository-wide correctness audit](repository-audit.md) found and
fixed large-batch address arithmetic, Eigen alignment and RL launch-bound issues.
It adds guarded arena tests and repeatable host/device sanitizer profiles; see
that report for the newer validation evidence and remaining tooling blockers.

Rendering, sensors, scene collision, interacting swarm physics and legacy
framework ABI/checkpoint equivalence remain excluded. Multi-GPU, hardware-counter
coverage and Compute Sanitizer under this WDDM host remain unqualified. Long
uninterrupted flight, broad model/policy distributions and trained-policy transfer
need their own measured qualification. The million-lane result remains a native
simulation capacity probe, not a million-agent PPO or CPU parity result.

For reproduction run `python3 scripts/local_ci.py verify` through Compose after
the documented setup. Focused regressions are in
`flightrl-cuda/tests/test_hardening.py`; benchmark reproduction uses the documented
RL command with `--lanes 1024,16384 --agents 1024 --workers 8 --modes thread
--samples 5 --warmup 2 --trace`.
